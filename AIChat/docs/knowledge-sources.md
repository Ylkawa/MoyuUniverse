# 知识事实与多来源

PostgreSQL `knowledge_document` 继续逐 URL 保存来源文档；一个文档可以支持多个知识事实，一个知识事实也可以由多个文档支持。原始文档 ID 和 URL 哈希不变。

Qdrant 每个事实点新增：

- `sources`：数组，每项含 `document_id`、`url`、`title`、`query`、`conclusion`、`confidence`、`ttl`。每个来源独立保留实际陈述、支持程度和复查期限。
- `source_urls`、`document_ids`：来源 URL 和文档 ID 数组。
- 顶层 `document_id`、`query`、`conclusion`、`confidence` 作为代表来源的兼容字段；顶层 `ttl` 为各来源期限的最大值。查询时再逐来源过滤到期项。

入库先生成问答与向量，在知识集合中取最多 10 个相似候选（阈值 0.6）。相似度仅用于召回；文本完全相同或模型确认主体、范围、完整结论与证据状态一致，才把新来源关联到已有点。模型只作每条新知识一次候选选择；相关但不等价、冲突或不确定的陈述另存。来源增加不自动提高置信度，也不把转载自动视为独立验证。

同一 KnowledgeStore 实例内，同步入库与后台队列共用串行写入锁。先完成新事实写入，再移除该文档不再支持的旧事实关联；仍有其他来源的点继续保留。部分写入失败时不清理旧关联，允许重试收敛。不同应用实例之间没有分布式写锁，应保持单写入实例。

旧点没有 `sources` 时，依据原 `document_id` 从文档库恢复单来源；后续合并时沿用原点 ID、向量和创建时间并补齐来源数组。此兼容读取不代表历史重复点已全部合并；未执行全库清理或生产迁移。新程序启动会为 `document_ids` 创建载荷索引，无需修改 SQL 表。

检索问答附带各自来源数组，主助手与研究助手均获得相应 URL 和各来源陈述；全文内容仍对应代表来源文档。旧版程序的单文档重建逻辑不了解共享来源，因此一旦产生多来源点，不应让旧版写入程序继续处理同一集合。

离线测试使用内存 gRPC 通道验证真实 Qdrant SDK 请求及合并、重建、到期、失败、重试、旧点兼容行为；不证明真实 Qdrant、SQL、Embedding 或模型语义判断的线上效果。
